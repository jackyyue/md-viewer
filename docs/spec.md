# md-viewer 第一版 spec

## 一句话

点开一个文件夹，立刻以只读方式浏览里面的 Markdown：左侧目录树加当前文件的标题大纲，右侧渲染结果。替代"为看几个 md 而建一个 Obsidian vault"这个动作。

## 范围

**只服务**研究笔记这类纯 md 文件夹。验收标准：`D:\oss-agent\paseo\wiki` 里 42 篇全部正常渲染。

本版不做：编辑与保存、新建与重命名与删除、打印、跨文件全文搜索、非 md 文件展示、大库优化（虚拟滚动）。

## 决策清单

### 1. 只读

不含任何写入操作。要改笔记时用编辑器，不在这个工具里改。

### 2. 形态：本地小服务 + 系统浏览器标签页

- 双击或拖拽启动一个小程序，它起本地服务，然后调用系统默认浏览器打开一个标签页
- 界面就在那个标签页里（能看到地址栏和标签页）。这是刻意的取舍：独立窗口外壳（Tauri/WebView2）要多写一层，而且外壳里的打印对话框比浏览器弱——第二版做打印时，浏览器形态反而是优势
- 本地服务是必需的，不是选择：浏览器无法列出任意文件夹的内容，`file://` 也不行

### 3. 启动方式

- `md-viewer.cmd <文件夹路径>`：命令行传库根
- 把文件夹拖到 `md-viewer.cmd` 上：等价于传参
- 不带参数双击：弹文件夹选择框
- 无 Windows 右键菜单集成（那要改注册表，且要处理路径带空格与日后卸载，成本高于收益）

### 4. 生命周期

- `.cmd` 窗口开着，服务就在跑；关掉窗口即停
- 每次启动自动挑一个空闲端口，多个实例互不干扰（不做端口复用与单实例检测）
- 不写文件监听。用 agent 改这些 md 的过程中界面不会自己更新，按 F5 手动刷新

### 5. 库边界与链接

- 库根 = 启动时传入的文件夹，这是唯一的边界
- md 里的相对链接：指向库内的跳转，指向库外的置灰不可点（或点击提示"在库外"）
- 所有涉及路径的请求都必须做越界校验，库外的路径一律拒绝

### 6. 目录树

- 显示：文件夹 + `.md` 文件
- 隐藏：所有 `.` 开头的目录（`.git`、`.obsidian`、`.agent-runs`），以及内置忽略名单 `node_modules`、`dist`、`build`、`.venv`
- 不显示非 md 文件（图片、pdf 等）

### 7. 大纲

左树下方一个可折叠区，列出当前文件的 H1/H2/H3，点击跳到对应位置。渲染时顺手收集标题即可，不额外解析。

### 8. 渲染范围

做：标题、段落、列表、引用块、加粗斜体、行内代码、围栏代码块、表格、链接。

不做：脚注、任务列表勾选框、数学公式、mermaid。（`paseo\wiki` 里这些出现次数为 0，图片也是 0）

代码块高亮规则：

- **不用深色底**。用白底或极浅灰底加深色文字
- 关键字除了颜色还要**同时加粗**——黑白打印机上颜色会变灰，只靠颜色区分不出来
- 高亮库离线内置，运行时不许联网

frontmatter：用灰色小字显示，不隐藏。隐藏会让人以为文件是空的。

### 9. 技术栈

Node + TypeScript。理由：机器上 Node 现成；`jy-md2pdf\scripts\md2pdf.mjs` 里已有一个跑通的 md→HTML 转换器，覆盖的正是这些文件用到的语法子集，可以直接借用思路或代码；不需要引入第二个运行时。

### 10. 性能线

- 单库文件数 ≤ 2000，单文件 ≤ 2MB
- 超出时明确提示"这个库太大"，而不是卡死
- 实测背景：目录树一次读 2000 个文件名是毫秒级，不是瓶颈；瓶颈在渲染大单文件，所以上限主要卡单文件大小

## 已知坑

- **文件名可能含 `=`、`@`、中文和空格**（`paseo\wiki` 里 `2026-09-14=作者如何一个人做出paseo.md` 这类很常见）。所有 URL 与请求参数必须编码，不能直接拼字符串
- 库根路径可能含空格（Windows 上很常见），`.cmd` 里所有路径引用都要加引号

## 实测（2026-09-23，拿 `paseo\wiki` 当样本）

- 42 篇全部渲染成功，42 篇都有大纲；没有残留的代码围栏，也没有没解析掉的表格行
- 表格：11 个文件共 30 个表格，与源文件里的表格数量一致
- 6 种越界请求（`../../windows/win.ini`、URL 编码形式、`C:/...`、`/etc/passwd`、`sub/../../../etc/passwd`、空路径）全部 403
- 链接实测：293 个相对 md 链接里，可点 166、指向库外 64、死链 63
- 库根的选择直接决定可点率：`wiki` 根 57%（42 个 md）、`paseo` 根 77%（210 个）、`oss-agent` 根 78%（4971 个，超 2000 上限会被拒）
- 单元测试 26 个用例，全量 0.4 秒

## 不在本版：其他候选

- 允许跟随指向库外的链接（现在一律置灰）。实测库外链接占 22%；如果读笔记时经常要跳到 `docs/` 或相邻的 wiki，这条会变成刚需
- 给库加搜索路径：打开 `wiki` 时把 `paseo` 仓库根也纳入，只用于解析链接，不显示在树里
- 跨文件全文搜索（现在只能靠浏览器 Ctrl+F 找单篇内文）

## 不在本版：打印

第二版做。要点先记下来，免得到时重新想：

- 走浏览器自带的打印对话框，它有预览、打印机选择、双面、每张纸 2 页。不需要任何外部工具，也不产生 PDF 文件（浏览器内部排版是内存里的实现细节）
- 排版规格**沿用 `jy-md2pdf` 那套已验收的**，不要重调：A4；页边距 `24mm 22mm 26mm 22mm`；正文 10.67pt、行高 1.6；H1 16pt / H2 12.67pt / H3 10.67pt；行内代码 9.33pt；代码块 7.33pt；表格 9pt；页脚 9pt；每篇从新页开始；`pre` 整体不跨页；页脚"第 N 页 / 共 M 页"加创建日期
- 那套字号是**专门为 2-up 缩印调大的**，这不是美观问题，是可用性问题，别按屏幕观感改
- 屏幕渲染和打印共用同一个渲染器和同一份 HTML，只套两套 CSS
- 参考实现：`C:\Users\jack_\.codex\skills\jy-md2pdf`（含 `references/print-spec.md` 的完整规格与 Chrome 缩放怪癖说明）
- 待验证：浏览器对话框里选"每张纸 2 页"直接打印，与现在走 PDF 再打印，页数和观感是否一致。这一条不能当假设

## 验收

1. `md-viewer.cmd D:\oss-agent\paseo\wiki` 能起来，浏览器自动打开，42 篇逐个点开渲染无破格
2. `2026-09-14=作者如何一个人做出paseo.md` 这类含 `=` 和中文的文件名能正常打开
3. md 里的库内相对链接能跳转；`../../pi/wiki/pi/2026-09-14-pi-project-history.md` 这类库外链接不可点
4. 手工构造一个越界请求（如 `/../../windows/win.ini`），服务拒绝
5. 代码块在白底上可读，关键字即使去掉颜色也能靠加粗区分
6. 单文件超过 2MB 或库内文件超过 2000 时给出明确提示，不卡死
