# 未启用清单

这里只放**现在不做、条件到了会做**的东西。已经决定永远不做的不写在这里，写进 `rejected/`。

本表**只收规则和文档**，不收功能待办。“这个功能放到第二版”这类暂缓项写进 `spec.md` 的「不在本版」一节。

升格动作：条件命中 → 把 `_candidates/<文件>` 移到 `docs/` → 删掉本表对应行 → 在 `docs/index.md` 和 `AGENTS.md` 工作信号表里补引用。

## 候选规范

- `_candidates/coding-standards.md` — 出现第 2 个同类模块时启用
- `_candidates/testing.md` — 要写第 2 个测试文件时启用
- `_candidates/qa.md` — 第 1 次出现回归或跨模块缺陷时启用
- `_candidates/release.md` — 项目第一次对外发布时启用

## 依赖项目形态

- 平台/受测面矩阵 → 条件：项目出现第二个真实的运行目标或发布渠道
- 协议前后兼容与打点标记 → 条件：项目对外提供接口且已有外部消费者
- 发布渠道验收清单 → 条件：项目进入多渠道发布阶段
- 移动端测试流程 → 条件：项目有移动端构建
- 桌面打包冒烟 → 条件：项目有桌面打包产物
- 浏览器端到端 → 条件：项目有真实浏览器界面

## 依赖技术栈

- TypeScript 专属条款（见 `_candidates/coding-standards.md` 末尾「仅 TypeScript 适用」段）→ 条件**已命中**（本项目用 TypeScript，2026-09-23）。但父文档的升格条件（出现第 2 个同类模块）未到，条款暂留候选处
- React 专属条款（同上「仅 React 适用」段）→ 条件：项目使用 React
- DOM 组件测试与浏览器测试模式 → 条件：项目有前端渲染层

## 依赖工具链

- 禁止在本地跑全量测试 → 条件：测试套件超过 1 分钟。本项目的全量套件是 26 个用例 / 0.4 秒，这条禁令此时只会阻止验证
- 禁止重跑别人已报告全绿的套件 → 条件：项目接入 CI，且有别人（人或 CI）先报过绿
- 全量测试交给 CI → 条件：项目接入 CI，且本地跑一次全量比推一次 CI 慢
- 按文件名后缀区分测试类别 → 条件：测试框架支持按后缀或 glob 选测试
- CI 按改动路径路由 → 条件：项目有 CI 且测试套件超过 5 分钟
- 必需的检查项静态命名 → 条件：项目有分支保护或多腿 CI

## 依赖协作形态

- 问题追踪器工作流（拆票、triage 标签、决策票）→ 条件：项目接入真实的问题追踪器
- 并行多 agent 分工与 worktree 隔离 → 条件：同一时间有 2 个以上 agent 在同一仓库工作
- 长跑 subagent 编排与两段式审查 → 条件：需要 agent 自主连续工作 1 小时以上
